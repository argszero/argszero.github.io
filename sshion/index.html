sshion

把手机接回你已经能登录的那台机器所在的网络。

你手上本来就有一台能 ssh 登录的机器。打开这一版 App 里的连接以后， 手机的上网流量就从那台机器所在的网络出去 —— 相当于你人回到了那个网络里。 那台机器上什么都不用装，防火墙也不用改：用的就是你已经在用的 SSH 账号和密钥。

什么时候用得上

  • 在外访问公司内网：出差或在路上，用手机看公司内部的页面和后台，不必背着电脑，也不必先连公司 VPN。
  • 在外访问家里的设备：家里那台一直开着的 NAS 或小主机，人在外面也能进去。

开始之前

  • 一台你能 ssh 登录的服务器（标准 sshd 即可）。
  • 一把 Ed25519 私钥，或者密码。

怎么用

  1. 在 App 里填服务器地址、端口和用户名。
  2. 导入一把私钥，或者填密码。也可以直接点「Generate a new key pair」生成一把新密钥， 把那行公钥加到服务器的 ~/.ssh/authorized_keys。
  3. 点 Connect。第一次连接会记住服务器的指纹；之后指纹变了，App 会拒绝连接。

限制

  • 经过隧道的是走系统代理的 App —— Safari 和大部分原生网络请求。 用它自己裸连接、或者走 UDP / QUIC 的 App，在隧道开着的时候会连不上，断开就恢复。
  • 不支持 UDP，所以语音通话、部分视频和游戏不行。
  • 隧道开着时耗电会明显增加。
  • SSH 只能走 TCP，而 TCP 又套在 TCP 里，所以弱网下速度会明显下降。

排错

  • 连上了但网页打不开：先看 App 里的日志（右上角那个放大镜图标）。
  • 「Test the tunnel」：它会从 App 自己的进程穿过隧道发一个请求， 并显示对端看到的出口 IP。这一步成功，说明隧道本身是通的；如果 Safari 仍然打不开，问题在系统代理这一侧。
  • 换过服务器或重装过系统：在 App 里点「Forget host key」再重连。指纹变化是正常的， 但默认按安全处理 —— 直接拒绝，而不是静默接受。
